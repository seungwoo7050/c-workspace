# 리스트 변환 도중 할당 실패 시 부분 결과 롤백하기

**Lv2-core / 자원 관리**

**프로젝트에서** `src/list/ft_list.c`의 `ft_lstmap()`이 원본 리스트를 순회하며 변환된 새 리스트를 만드는 도중, 새 노드 할당(`ft_lstnew`)이 실패하면 지금까지 만든 새 리스트 전체를 정리하고 나서야 `NULL`을 반환한다.

```c
node = ft_lstnew(mapped_content);
if (node == NULL) {
    del(mapped_content);       // 이번 변환 결과 정리
    ft_lstclear(&mapped, del); // 이미 만든 새 리스트 전체도 정리
    return (NULL);
}
```

**일반적으로** 여러 단계를 거쳐 자원(메모리, 파일 핸들, 락 등)을 누적해서 만드는 함수가 중간에 실패하면, 두 가지 선택지가 있다.

1. 이미 만든 부분 결과를 그대로 두고 실패만 알린다.

2. 실패 시점까지 만든 것들을 전부 정리(롤백)하고 나서 실패를 알린다.

첫 번째 방식은 함수 시그니처가 단순해 보이지만, 호출자가 "실패했다는 반환값(`NULL`)을 받았는데 그 전에 만들어진 자원은 누가 정리하는가"를 알 방법이 없다는 문제가 남는다. 결과적으로 메모리/자원 누수로 이어지거나, 호출자가 "실패해도 부분 결과가 있을 수 있다"는 걸 알고 별도로 처리해야 하는 부담이 생긴다. 두 번째 방식(이 프로젝트가 택한 방식)은 "이 함수가 실패로 반환하면, 그 함수가 만든 것은 아무것도 남아있지 않다"는 단순하고 예측 가능한 계약을 제공한다.

**모범사례**:  
이 "전부 성공하거나 전부 롤백한다"는 원칙은 데이터베이스 트랜잭션의 원자성(atomicity)과 정확히 같은 개념이다. C++의 RAII나 Rust의 소유권 시스템은 이런 롤백을 소멸자/드롭 시점에 자동으로 처리해주지만, C에는 그런 언어 차원의 도움이 없어서 이 롤백 로직을 매번 손으로 정확히 짜야 한다. `ft_lstmap`처럼 실패 지점에서 "지금까지 무엇을 만들었는지"를 정확히 추적하고 그걸 정리하는 코드를 실패 분기마다 직접 넣는 것이, C에서 이 원자성 계약을 지키는 사실상 유일한 방법이다.
