# 키로 찾아가는 연결 리스트로 여러 핸들의 상태를 독립적으로 관리하기

**Lv2-core / 자료구조**

**프로젝트에서** `get_next_line.c`가 파일 디스크립터(fd)마다 독립된 `t_reader` 노드를 연결 리스트로 관리하고, 매 호출마다 그 fd에 해당하는 노드를 찾아 쓴다.

```c
static t_reader *find_reader(int fd) {
    reader = g_readers;
    while (reader != NULL && reader->fd != fd)
        reader = reader->next;
    return (reader); // 없으면 NULL → 호출부가 create_reader로 새로 만듦
}
```

**일반적으로** "여러 독립적인 개체 각각에 대해 상태를 유지해야 한다"는 요구가 생기면(이 프로젝트의 fd, 웹 서버의 세션, 게임의 플레이어 등), 그 상태를 무언가로 "찾아갈 수 있게" 만들어야 한다. 여기서는 연결 리스트에 순차 탐색(fd가 같은 노드를 찾을 때까지 `next`를 따라감)을 쓴다. 구현이 단순하고, 동시에 열린 파일 개수가 적은 상황(이 프로젝트의 실제 사용 맥락)에서는 이 $O(n)$ 탐색 비용이 무시할 만하다.

**모범사례**:  
동시에 추적해야 하는 키의 개수가 많아지면(수천 개의 fd, 수만 명의 동시 접속자) 순차 탐색은 병목이 된다. 그런 규모에서는 해시맵(`std::unordered_map`, C의 해시테이블 구현 등, $O(1)$ 평균 조회)이나 배열 인덱싱(fd 자체가 작은 정수라는 걸 이용해 `readers[fd]`처럼 직접 인덱싱하는 방법도 가능)으로 바꾸는 게 일반적이다. "몇 개까지 다뤄야 하는가"라는 규모의 질문이 "어떤 자료구조가 적절한가"라는 질문의 답을 바꾼다는 걸 보여주는 사례다. 단, 이 프로젝트 규모에서는 연결 리스트로 충분했다.
