# INT_MIN을 안전하게 절댓값으로 바꾸는 방법

**Lv1 / C 기초**

**프로젝트에서** `src/ft_number.c`의 `ft_printf_print_signed()`가 음수를 출력할 때 `-value`를 직접 계산하지 않는다.

```c
if (value < 0)
    return (ft_write_decimal(ctx, fmt, "-", (unsigned long)(-(value + 1)) + 1));
```

**일반적으로** 2의 보수(대부분의 현대 CPU가 쓰는 정수 표현)에서 `n`비트 부호 있는 정수의 표현 범위는 `-2^(n-1)`부터 `2^(n-1) - 1`까지다. 음수 쪽이 양수 쪽보다 정확히 1개 더 표현 가능하다. 그래서 최솟값(`INT_MIN`)은 그 절댓값(`2^(n-1)`)이 같은 폭의 부호 있는 타입으로 표현 불가능한 유일한 값이다. `-INT_MIN`을 그대로 계산하면 이 값을 만들려다 표현 범위를 넘어서는 오버플로가 나고, signed 정수의 오버플로는 C 표준상 undefined behavior다.

이를 피하는 표준적인 트릭이 "표현 가능한 값으로 먼저 옮겨서 계산한다"는 것이다. `value + 1`은 `INT_MIN + 1`로, 안전하게 표현 가능한 값이다. 이 값을 음수화(`-(value + 1)`)하면 결과는 `INT_MAX`와 같은 범위 안에 있어 안전하고, 마지막에 1을 더하면 원래 원했던 `INT_MIN`의 절댓값이 나온다. 계산 도중 한 번도 표현 불가능한 값을 만들지 않으면서 같은 결과에 도달하는 것이다.

**모범사례**:  
더 간단한 대안은 애초에 음수화를 더 넓은 타입에서 하는 것이다(예: `int`를 먼저 `long long`으로 확장한 뒤 음수화. 이 프로젝트도 실제로 `(long)number`로 한 번 확장한다). 다만 그 넓은 타입조차 원래 타입과 폭이 같을 수 있는 플랫폼(예: `int`와 `long`이 둘 다 32비트인 환경)을 고려하면, "타입을 넓힌다"는 방법 자체가 플랫폼에 따라 안전을 보장 못 할 수 있다. 이 프로젝트가 `value + 1` 트릭을 쓴 이유는 이 방법이 타입 폭과 무관하게 항상 성립하는 더 견고한 해법이기 때문이다.
