# 검증 코드가 프로덕션 로직을 공유하면 안 되는 이유

**Lv1 / 테스트**

**프로젝트에서** `src/checker.c`가 `push_swap`의 정렬 함수를 전혀 재사용하지 않는다. 같은 원본 입력을 독립적으로 다시 받아, `push_swap`이 출력한 명령을 그대로 재실행한 뒤 정렬 여부만 확인한다.

```c
// checker.c는 sort.c(push_swap의 정렬 알고리즘)를 import하지 않는다
// 오직 "이 명령들을 그대로 실행하면 정렬된 상태가 되는가"만 확인한다
if (stack_is_complete_sorted(&a, &b))
    ps_putstr_fd(1, "OK\n");
```

**일반적으로** "결과를 만드는 코드"와 "그 결과가 맞는지 확인하는 코드"가 같은 로직 위에 세워져 있으면, 그 공유된 로직에 있는 버그는 두 곳 모두에 똑같이 나타난다. 검증 코드가 "틀린 답"을 "정답"이라고 착각하고 통과시켜버리는 것이다. 이건 단위 테스트를 짤 때도 똑같이 나타나는 함정이다. 테스트 코드가 프로덕션 함수 내부의 계산 로직을 그대로 복사해서 "기대값"을 계산하면, 그 로직에 버그가 있어도 테스트는 항상 통과한다.

**모범사례**:  
안전한 검증은 결과를 만드는 방법과 다른 독립적인 방법으로 정답 여부를 확인해야 한다. 이 프로젝트의 `checker`는 "명령대로 실제로 실행해봤을 때 최종 상태가 정렬됐는가"라는, `push_swap`이 어떤 알고리즘을 썼는지와 전혀 무관한 방식으로 검증한다. 정렬 여부를 판정하는 로직(`stack_is_complete_sorted`)조차 정렬을 어떻게 만들었는지와는 완전히 별개다. 실무에서 "이 테스트가 실제로 버그를 잡을 수 있는가?"를 스스로 점검하는 가장 쉬운 방법은, 검증 코드 안에 프로덕션 코드와 같은 계산이나 가정이 몰래 섞여 들어가지 않았는지 확인하는 것이다.
