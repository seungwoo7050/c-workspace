# 함수 호출 사이에 부분 결과를 기억해야 하는 이유

**Lv1 / C 기초**

**프로젝트에서** `get_next_line.c`가 `static`(함수 호출이 끝나도 값이 유지되는) 상태에 "지금까지 읽었지만 아직 한 줄로 반환하지 않은 나머지 바이트"를 누적해둔다.

```c
static t_reader *g_readers; // 함수가 끝나도 사라지지 않는다

char *get_next_line(int fd)
{
    ...
    read_size = read(fd, ...); // read()는 딱 다음 BUFFER_SIZE바이트만 줄 뿐, 줄 경계를 모른다
    ...
}
```

**일반적으로** 대부분의 함수는 호출될 때마다 매개변수만으로 결과가 결정되는 순수 함수처럼 짜는 게 이해하기 쉽다(같은 입력 → 항상 같은 출력). 하지만 `get_next_line`처럼 "저수준 API(`read`)가 제공하는 단위(임의 크기의 바이트 뭉치)"와 "이 함수가 약속한 반환 단위(한 줄)"가 서로 다를 때는, 그 차이를 어딘가에 저장해뒀다가 다음 호출에서 이어받아야 한다. C에서 이런 "호출 간에 유지되는 상태"를 만드는 방법이 함수 내부의 `static` 변수(또는 파일 스코프 전역 변수)다. 이 변수는 프로그램이 끝날 때까지, 또는 명시적으로 정리할 때까지 값을 유지한다.

**모범사례**:  
`static`/전역 상태는 그 자체로 위험 요소이기도. 하다. 여러 스레드가 동시에 같은 `get_next_line`을 호출하면 이 상태를 서로 덮어써서 경쟁 상태(data race)가 생긴다(이 구현은 멀티스레드 안전을 스코프에 넣지 않았다). 더 큰 시스템에서는 이런 **"호출 간 유지되는 상태"를 전역 변수 대신 호출자가 명시적으로 들고 다니는 핸들/컨텍스트 객체(`t_reader *ctx`를 매개변수로 받는 형태)로 만드는 게 일반적**이다.
